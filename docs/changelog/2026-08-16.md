## ★ RabbitMQ 4.x — Celery crash-looped, votes stuck unverified

**Symptom** Worker never started. Crash loop on
`INTERNAL_ERROR - Feature 'transient_nonexcl_queues' is deprecated`, then
`RestartFreqExceeded: 5 in 1s`. With no worker alive, cast ballots stayed
unverified and the admin UI refused to tally: *"2 votes still being processed."*
The ballots were never lost — just unattended.

**Cause** RabbitMQ 4.0 stopped permitting *transient non-exclusive queues*. Celery
declares queues of exactly that kind at startup for worker coordination.
`--without-mingle --without-gossip` was **not** sufficient: a third consumer
(pidbox, the remote-control channel) declares its own queue regardless of those flags.

**Fix** Created `/opt/homebrew/etc/rabbitmq/rabbitmq.conf` (did not exist), then
restarted the broker (`brew services restart rabbitmq`):

```
deprecated_features.permit.transient_nonexcl_queues = true
```

Chosen over disabling Celery features piecemeal, so `--events`, `--beat`, mingle and
gossip all keep working. Two dead ends worth not repeating:

- `rabbitmqctl enable_feature_flag transient_nonexcl_queues` — **does not work**;
  the flag no longer exists in 4.x, this is config-file-only.
- An earlier `CELERY_WORKER_ENABLE_REMOTE_CONTROL` setting in `settings.py` was
  **reverted**; the broker-side fix makes it unnecessary and `settings.py` is now
  byte-identical to upstream.

**Verified** Worker reaches `celery@… ready`; `transient_nonexcl` error count **0**.

## ★ Celery 5.6.1 → 5.6.3 — per-task database connection leak

**Symptom** Once the broker was fixed, the worker started but raised `AttributeError`
**312 times in ~30 seconds** — once per task — from `celery/fixups/django.py`.

**Cause** A Celery bug: it reads `.__module__` on `pool_cls`, which is a string at
that point. The failing line sits **above** the `conn.close()` loop in the same
function, so **no database connection was ever closed after a task** — a per-task
leak that would compound during the Milestone 10 sweep.

**Fix** One line — `pyproject.toml`, `celery==5.6.1` → `celery==5.6.3`. Upstream
fixed this in 5.6.2; the project was pinned one version behind it. No code changes.
